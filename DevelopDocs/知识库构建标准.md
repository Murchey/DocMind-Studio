# 知识库构建标准

> 定义 DocMind-Studio 项目知识库的输入输出格式、字段结构、manifest 规范。
> **v2.0 更新**：支持增量更新——通过 `content_hash` 指纹检测文档变更，仅处理差异部分。
> **v3.0 更新**：支持多源注册——任意 Agent 可通过 `register` 命令将输出元数据注册到项目级知识库；新增实体/关系索引（人物、术语、作品）；支持 `query` 查询命令。

涉及 skill/agent/workflow 为：
- knowledge-builder (workflow)
- doc-content-analysis (agent)
- excel-master (agent)
- ppt-master (agent)
- ppt-deep-summary (agent)
- phd-research-agent (agent)

---

## 输入

### doc-content-analysis 输入

输入内容是文本文档和其他格式的文档。支持两种文档类型：

| 文档类型 | 说明 | 输出目标 |
|----------|------|----------|
| **知识文档** | 技术文档、研究报告、论文等 | knowledge-builder |
| **需求文档** | 排课要求、表格分析需求等 | excel-master |

| 格式 | 说明 |
|------|------|
| `.docx` | Word 文档（直接处理） |
| `.doc` | 旧版 Word 文档（需转换） |
| `.pdf` | PDF 文档（需转换） |
| `.txt` | 纯文本 |
| `.pptx` | PowerPoint 演示文稿 |
| `.ppt` | 旧版 PowerPoint |
| `.xlsx` | Excel 表格 |
| `.xls` | 旧版 Excel |
| `.md` | Markdown 文档 |

### phd-research-agent 输入

输入内容是 Markdown 或纯文本格式的研究相关内容。

| 任务类型 | 输入文件 | 说明 |
|----------|----------|------|
| Idea 评估 | `idea.md` | 研究想法描述 |
| Introduction 起草 | `research_info.md` | 研究信息（领域、局限性、挑战等） |
| 论文审阅 | `draft.md` | 论文草稿 |

### 输入路径

doc-content-analysis:
```
WORKSPACE/{ProjectName}/doc-content-analysis/input/
├── *.doc
├── *.docx
├── *.pdf
└── *.txt
```

phd-research-agent:
```
WORKSPACE/{ProjectName}/phd-research-agent/input/
└── <task_type>.md
```

## 输出

### 输出路径

```
WORKSPACE/{ProjectName}/doc-content-analysis/summary/
├── manifest.json              # 处理清单（调度器入口）
├── <文件名1>/
│   ├── text/
│   │   ├── content.json       # 结构化文档内容
│   │   ├── summary.json       # 结构化总结索引
│   │   └── summary.md         # 可读总结
│   └── img/
│       ├── image_1.png
│       ├── text/              # OCR 结果
│       └── img-summary/       # AI 视觉总结
└── 综合总结.json/md           # 多文档综合总结
```

### 知识库路径（项目级）

知识库统一存放在项目根目录下的 `knowledge-base/` 中，支持多 Agent 共享：

```
WORKSPACE/{ProjectName}/knowledge-base/
├── .kb_state.json             # 知识库状态（版本号、指纹、来源追踪）
├── kb-manifest.json           # 知识库清单（全局摘要）
├── toc.json                   # 目录结构
├── documents/                 # 文档索引（含实体）
│   └── <doc_id>.json
├── keywords/                  # 关键词索引
│   └── index.json
├── concepts/                  # 概念索引
│   └── index.json
├── entities/                  # 实体索引（v3.0 新增）
│   └── index.json
└── relations/                 # 关系索引（v3.0 新增）
    └── index.json
```

## 核心字段定义

### 单文档总结 (summary.json)

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 文档唯一标识，如 `doc_001` |
| `title` | string | 是 | 文档标题 |
| `source_file` | string | 是 | 原始文件名 |
| `document_type` | string | 是 | 文档类型：`knowledge`（知识文档）/ `requirement`（需求文档） |
| `author` | string | 否 | 作者 |
| `created_at` | string | 否 | 文档创建时间 |
| `paragraph_count` | int | 是 | 段落数量 |
| `table_count` | int | 是 | 表格数量 |
| `image_count` | int | 是 | 图片数量 |
| `language` | string | 是 | 文档语言（`zh`/`en`） |
| `generated_at` | string | 是 | 生成时间（ISO 8601） |
| `summary` | string | 是 | 文档摘要（200-300字） |
| `keywords` | array | 是 | 关键词列表 |
| `sections` | array | 是 | 章节结构 |
| `key_info` | object | 是 | 关键信息 |
| `tables` | array | 否 | 表格索引 |
| `images` | array | 否 | 图片索引 |
| `content_links` | object | 是 | 内容链接 |

### 需求文档扩展字段

当 `document_type` 为 `requirement` 时，必须包含以下字段：

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `requirement_type` | string | 是 | 需求类型：`schedule` / `excel` / `general` |
| `target_agent` | string | 是 | 目标 Agent：`excel-master` |
| `requirements` | object | 是 | 需求详情 |
| `requirements.task_description` | string | 是 | 任务描述 |
| `requirements.constraints` | array | 否 | 约束条件列表 |
| `requirements.inputs` | array | 否 | 所需输入列表 |
| `requirements.expected_output` | string | 否 | 期望输出描述 |

### keywords 字段结构

```json
{
  "keyword": "关键词文本",
  "frequency": 12,
  "relevance": 0.95
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `keyword` | string | 关键词 |
| `frequency` | int | 词频 |
| `relevance` | float | 相关度（0-1） |

### sections 字段结构

```json
{
  "heading": "章节标题",
  "level": 2,
  "paragraph_range": [1, 15],
  "key_points": ["要点1", "要点2"],
  "content_link": "{workspace}/summary/<文件名>/text/content.json#/paragraphs/0-14"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `heading` | string | 章节/主题名称 |
| `level` | int | 标题层级（1/2/3） |
| `paragraph_range` | array | 段落范围 [起始, 结束] |
| `key_points` | array | 要点列表 |
| `content_link` | string | 指向 content.json 的链接 |

### key_info 字段结构

```json
{
  "data": [{"value": "关键数据", "location": "paragraph_5"}],
  "conclusions": [{"text": "核心观点", "location": "paragraph_12"}],
  "references": [{"text": "重要引用", "location": "paragraph_20"}]
}
```

| 子字段 | 类型 | 说明 |
|--------|------|------|
| `data` | array | 关键数据/数字 |
| `conclusions` | array | 核心结论 |
| `references` | array | 重要引用 |

### tables 字段结构

```json
{
  "index": 0,
  "description": "表格内容简要描述",
  "rows": 5,
  "columns": 4,
  "location": "paragraph_8",
  "content_link": "{workspace}/summary/<文件名>/text/content.json#/tables/0"
}
```

### images 字段结构

```json
{
  "file": "image_1.png",
  "path": "{workspace}/summary/<文件名>/img/image_1.png",
  "description": "图片内容简要描述",
  "has_text": true,
  "ocr_link": "{workspace}/summary/<文件名>/img/text/image_1.txt",
  "summary_link": "{workspace}/summary/<文件名>/img/img-summary/image_1.md"
}
```

## 实体与关系索引（v3.0 新增）

knowledge-builder 从文档内容中自动提取实体（人物、术语、作品），并构建跨文档关系索引。

### entities/index.json 结构

```json
{
  "generated_at": "2024-01-01T12:00:00+00:00",
  "total_persons": 15,
  "total_terms": 42,
  "total_works": 8,
  "persons": [
    {
      "name": "马克思",
      "total_count": 12,
      "document_count": 3,
      "documents": [
        {"id": "doc_001", "count": 5},
        {"id": "doc_002", "count": 7}
      ]
    }
  ],
  "terms": [
    {
      "name": "Historical Materialism",
      "total_count": 8,
      "document_count": 2,
      "documents": [
        {"id": "doc_001", "count": 3},
        {"id": "doc_003", "count": 5}
      ]
    }
  ],
  "works": [
    {
      "name": "资本论",
      "total_count": 6,
      "document_count": 2,
      "documents": [
        {"id": "doc_001", "count": 4},
        {"id": "doc_002", "count": 2}
      ]
    }
  ]
}
```

**实体类型说明**：

| 实体类型 | 提取规则 | 过滤阈值 | 最大数量 |
|----------|----------|----------|----------|
| `persons` | 中文姓氏 + 1-2 字名，排除常见非人名词组 | 出现 ≥ 2 次 | 30 |
| `terms` | 英文多词术语、中文学术术语（观/论/说/主义等后缀） | 出现 ≥ 2 次 | 50 |
| `works` | 书名号 `《》` 包裹的内容 | 出现 ≥ 1 次 | 30 |

### relations/index.json 结构

```json
{
  "generated_at": "2024-01-01T12:00:00+00:00",
  "total_relations": 5,
  "relations": [
    {
      "source": "doc_001",
      "target": "doc_002",
      "type": "shared_terms",
      "weight": 3,
      "details": ["Historical Materialism", "辩证法", "唯物主义"]
    },
    {
      "source": "doc_001",
      "target": "doc_003",
      "type": "shared_works",
      "weight": 2,
      "details": ["资本论", "共产党宣言"]
    }
  ]
}
```

**关系类型说明**：

| 关系类型 | 说明 |
|----------|------|
| `shared_terms` | 两篇文档共享的术语集合 |
| `shared_works` | 两篇文档共同引用的作品 |

### 单文档 entities 字段（documents/<id>.json 中）

每个文档索引中包含从内容提取的实体数据：

```json
{
  "id": "doc_001",
  "title": "文档标题",
  "entities": {
    "persons": [
      {"name": "马克思", "count": 5}
    ],
    "terms": [
      {"name": "Historical Materialism", "count": 3}
    ],
    "works": [
      {"name": "资本论", "count": 4}
    ]
  },
  "related_documents": [
    {
      "id": "doc_002",
      "relation": "共享关键词",
      "shared_keywords": ["唯物主义", "辩证法"]
    }
  ]
}
```

## kb-manifest.json 结构（v3.0 新增）

知识库级别的全局清单，由 `kb_manager.py` 自动维护：

```json
{
  "format_version": "2.0",
  "version": 3,
  "name": "knowledge-base",
  "generated_at": "2024-01-01T12:00:00+00:00",
  "document_count": 10,
  "keyword_count": 45,
  "concept_count": 12,
  "entity_count": 65,
  "relation_count": 8,
  "sources": ["doc-content-analysis", "ppt-deep-summary", "excel-master"],
  "documents": [
    {
      "id": "doc_001",
      "title": "文档标题",
      "source_file": "report1.docx",
      "source_agent": "doc-content-analysis",
      "added_at": "2024-01-01T12:00:00+00:00",
      "updated_at": "2024-01-01T12:00:00+00:00",
      "content_hash": "sha256...",
      "index_link": "documents/doc_001.json"
    }
  ],
  "top_keywords": [
    {"keyword": "关键词", "document_count": 5, "total_frequency": 20}
  ],
  "top_concepts": [
    {"concept": "概念名", "document_count": 3, "importance": 0.9}
  ],
  "change_log": []
}
```

**关键字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `sources` | array | 贡献文档的 Agent 名称列表 |
| `documents[].source_agent` | string | 该文档的来源 Agent |
| `entity_count` | int | 实体总数（persons + terms + works） |
| `relation_count` | int | 关系总数（shared_terms + shared_works） |

## kb_manager.py 命令（v3.0 新增）

knowledge-builder 提供五种命令模式，通过 `kb_manager.py` 调用：

### init — 首次全量构建

```bash
python kb_manager.py init <kb_dir> <summary_dir> <manifest_path> [--agent <agent_name>]
```

| 参数 | 说明 |
|------|------|
| `kb_dir` | 知识库输出目录 |
| `summary_dir` | doc-content-analysis 的 summary 目录 |
| `manifest_path` | manifest.json 路径 |
| `--agent` | 来源 Agent 名称（默认 `doc-content-analysis`） |

首次构建会创建完整的知识库目录结构，包括 `documents/`、`keywords/`、`concepts/`、`entities/`、`relations/` 索引。

### update — 增量更新

```bash
python kb_manager.py update <kb_dir> <summary_dir> <manifest_path> [--agent <agent_name>]
```

通过 `content_hash` 指纹对比检测文档变更，仅处理差异部分。输出示例：

```
[INFO] Changes detected: +2 new, ~1 changed, -1 removed, =5 unchanged
[OK] Knowledge base updated to v4: +2 added, ~1 updated, -1 removed
```

### register — 跨 Agent 注册（v3.0 新增）

```bash
python kb_manager.py register <kb_dir> <agent_name> <manifest_path> [--summary-dir <dir>]
```

| 参数 | 说明 |
|------|------|
| `kb_dir` | 知识库目录 |
| `agent_name` | 注册的 Agent 名称（如 `ppt-deep-summary`、`excel-master`） |
| `manifest_path` | Agent 输出的 manifest.json 路径 |
| `--summary-dir` | summary 目录（可选，用于加载 summary.json） |

**支持两种 manifest 格式**：
1. **标准格式**：与 doc-content-analysis 兼容，包含 `documents[].status` / `summary_json`
2. **通用格式**：manifest 本身即文档描述，包含 `title` / `source_file` 字段

register 命令会自动：
- 提取实体（人物、术语、作品）
- 重建实体和关系索引
- 更新 `.kb_state.json` 和 `kb-manifest.json`
- 记录来源 Agent 到 `sources` 字段

### status — 查看状态

```bash
python kb_manager.py status <kb_dir> [--summary-dir <dir>] [--manifest <path>]
```

输出示例：

```
Knowledge Base Status (v3)
  Documents:  10
  Keywords:   45
  Concepts:   12
  Entities:   65
  Relations:  8
  Last updated: 2024-01-01T12:00:00+00:00

  Data Sources:
    - doc-content-analysis: 7 docs (last: 2024-01-01T12:00:00)
    - ppt-deep-summary: 3 docs (last: 2024-01-01T12:00:00)
```

### query — 查询知识库（v3.0 新增）

```bash
python kb_manager.py query <kb_dir> <query_type> <query_text>
```

| query_type | 说明 | 查询目标 |
|------------|------|----------|
| `keywords` | 关键词查询 | `keywords/index.json` |
| `entities` | 实体查询（人物/术语/作品） | `entities/index.json` |
| `documents` | 文档查询（标题/ID） | `.kb_state.json` |
| `relations` | 关系查询（共享术语/作品） | `relations/index.json` |

**查询示例**：

```bash
# 查询关键词
python kb_manager.py query knowledge-base/ keywords "唯物主义"

# 查询实体（人物、术语、作品）
python kb_manager.py query knowledge-base/ entities "马克思"

# 查询文档
python kb_manager.py query knowledge-base/ documents "资本论"

# 查询关系
python kb_manager.py query knowledge-base/ relations "doc_001"
```

## 跨 Agent 注册工作流（v3.0 新增）

v3.0 引入多源注册机制，允许任意 Agent 将输出元数据注册到项目级知识库，无需经过 doc-content-analysis 中转。

### 注册流程

```
Agent 完成任务 → 生成 manifest.json → register 到 knowledge-base/
    ↓
kb_manager.py register 自动处理：
    1. 加载 Agent 输出的 manifest.json
    2. 提取实体（人物/术语/作品）
    3. 更新 documents/<id>.json
    4. 重建 entities/index.json 和 relations/index.json
    5. 更新 .kb_state.json（sources + version）
    6. 更新 kb-manifest.json
```

### 各 Agent 注册方式

**ppt-deep-summary 注册**：

```bash
python kb_manager.py register \
  WORKSPACE/{ProjectName}/knowledge-base/ \
  ppt-deep-summary \
  WORKSPACE/{ProjectName}/ppt-deep-summary/summary/manifest.json \
  --summary-dir WORKSPACE/{ProjectName}/ppt-deep-summary/summary/
```

**excel-master 注册**：

```bash
python kb_manager.py register \
  WORKSPACE/{ProjectName}/knowledge-base/ \
  excel-master \
  WORKSPACE/{ProjectName}/excel-master/output/manifest.json \
  --summary-dir WORKSPACE/{ProjectName}/excel-master/output/
```

**phd-research-agent 注册**：

```bash
python kb_manager.py register \
  WORKSPACE/{ProjectName}/knowledge-base/ \
  phd-research-agent \
  WORKSPACE/{ProjectName}/phd-research-agent/summary/manifest.json \
  --summary-dir WORKSPACE/{ProjectName}/phd-research-agent/summary/
```

### 调度器集成示例

```python
import subprocess
from pathlib import Path

def register_agent_output(project_name: str, agent_name: str):
    """将 Agent 输出注册到项目级知识库"""
    root = Path(__file__).parent
    kb_dir = root / "WORKSPACE" / project_name / "knowledge-base"
    agent_ws = root / "WORKSPACE" / project_name / agent_name
    
    # 查找 manifest.json
    manifest = None
    for candidate in ["summary/manifest.json", "output/manifest.json"]:
        p = agent_ws / candidate
        if p.exists():
            manifest = p
            break
    
    if not manifest:
        print(f"[WARN] No manifest found for {agent_name}")
        return
    
    # 查找 summary 目录
    summary_dir = None
    for candidate in ["summary", "output"]:
        p = agent_ws / candidate
        if p.is_dir():
            summary_dir = p
            break
    
    cmd = [
        "python",
        str(root / "ComponentAgents/doc-content-analysis/SKILLS/knowledge-builder/scripts/kb_manager.py"),
        "register",
        str(kb_dir),
        agent_name,
        str(manifest),
    ]
    if summary_dir:
        cmd.extend(["--summary-dir", str(summary_dir)])
    
    subprocess.run(cmd, check=True)
```

### register 与 update 的区别

| 特性 | `update` | `register` |
|------|----------|------------|
| 适用场景 | doc-content-analysis 增量更新 | 任意 Agent 注册输出 |
| manifest 格式 | 必须为标准格式 | 支持标准格式和通用格式 |
| 差异检测 | 基于 `content_hash` 精确对比 | 基于 `content_hash` 跳过已存在文档 |
| 实体提取 | 增量合并 | 全量重建实体/关系索引 |
| 知识库不存在时 | 自动创建（fallback 到 init） | 自动创建 |

## phd-research-agent 输出结构

phd-research-agent 根据任务类型输出不同的结构化结果。

### 输出路径

```
WORKSPACE/{ProjectName}/phd-research-agent/summary/
├── manifest.json           # 处理清单
├── idea_result.json        # Idea 评估结果
├── idea_result.md          # Idea 评估报告（可读）
├── intro_outline.json      # Introduction 大纲
├── intro_outline.md        # Introduction 大纲（可读）
├── review_result.json      # 论文审阅结果
└── review_result.md        # 论文审阅报告（可读）
```

### Idea 评估结果 (idea_result.json)

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `source_file` | string | 是 | 原始文件名 |
| `generated_at` | string | 是 | 生成时间（ISO 8601） |
| `verdict` | string | 是 | 评估结论 |
| `scores` | object | 是 | 五维评分 |
| `fatal_flaws` | array | 是 | 致命缺陷列表 |
| `suggestions` | array | 是 | 改进建议 |

**verdict 取值**：
- `Strong Accept`：无致命缺陷，总分 ≥ 20
- `Accept with Revisions`：无致命缺陷，总分 < 20
- `Reject and Pivot`：存在致命缺陷

**scores 五维评分结构**：

```json
{
  "higher": 1-5,  // 更高：提升性能/效果
  "faster": 1-5,  // 更快：提升效率/速度
  "stronger": 1-5, // 更强：增强鲁棒性/泛化
  "cheaper": 1-5,  // 更省：降低成本/资源
  "broader": 1-5   // 更广：扩展应用场景
}
```

### Introduction 大纲 (intro_outline.json)

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `source_file` | string | 是 | 原始文件名 |
| `generated_at` | string | 是 | 生成时间（ISO 8601） |
| `paragraphs` | array | 是 | 六段式大纲 |
| `contributions` | array | 是 | 贡献列表 |

**paragraphs 六段式结构**：

| 索引 | purpose | 说明 |
|------|---------|------|
| 0 | 背景介绍 | 领域重要性、研究对象 |
| 1 | 现有工作 | 现有方法及其局限性 |
| 2 | 问题本质 | 核心问题、研究目标 |
| 3 | 关键挑战 | 技术难点、挑战列表 |
| 4 | 解决方案 | 方法概述、技术路线 |
| 5 | 贡献总结 | 明确列出贡献点 |

**paragraphs 字段结构**：

```json
{
  "purpose": "段落目的",
  "content": "要点内容"
}
```

### 论文审阅结果 (review_result.json)

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `source_file` | string | 是 | 原始文件名 |
| `generated_at` | string | 是 | 生成时间（ISO 8601） |
| `issues` | array | 是 | 问题列表 |
| `summary` | object | 是 | 问题统计 |
| `verdict` | string | 是 | 审阅结论 |

**verdict 取值**：
- `Ready`：可以提交
- `Needs Revision`：需要修改
- `Not Ready`：不适合提交

**issues 字段结构**：

```json
{
  "severity": "CRITICAL | MAJOR | MINOR",
  "category": "logic | grammar | format | figure",
  "location": "问题位置",
  "description": "问题描述",
  "suggestion": "修改建议"
}
```

**severity 说明**：

| 级别 | 说明 |
|------|------|
| CRITICAL | 致命问题，必须修复 |
| MAJOR | 严重问题，强烈建议修复 |
| MINOR | 轻微问题，建议修复 |

**summary 字段结构**：

```json
{
  "critical": 0,
  "major": 0,
  "minor": 0
}
```
